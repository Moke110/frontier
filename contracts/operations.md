# 操作白名单与指令白名单（v1）

本契约对应 `contracts/operations.json`（机读）与 `hostrun/operations.py`（执行）。
两者是同一份设计的两种呈现：注册表是数据，代码只按注册表校验与执行。契约文档与
注册表不一致即视为缺陷（离线测试会逐行比对）。

设计依据：ADR 0009 §4/§5。词汇以 `GLOSSARY.md` 为准：Operation whitelist、
Instruction whitelist、Intent judgement、Console command。

## 两层白名单如何工作

1. 飞书 owner 单聊消息先 `strip()`，再在**指令白名单**里做**精确匹配**：
   大小写、内部空格与标点都参与匹配，不做模糊/前缀/去标点匹配。
2. 命中即按注册表执行对应操作，并把操作的回执发回 owner。
3. 未命中不执行、不猜测，交给**意图判定**（#83）：只读运行把消息映射到操作
   白名单中的至多一个操作，再由 owner 在确认卡片上点击执行。
4. 明确排除的动作（初始化、更新知识库、停止服务、改代码/配置/权限）直接拒绝：
   需要终端交互的回复"请在控制台执行"，修改 frontier 自身的回复"无权限"。
5. 执行入口只接受**操作 id + 经参数 schema 校验的 params**，绝不把消息原文透传
   给 agent 或执行端。

## 操作注册表

| 操作 id | 说明 | 参数 | 飞书可见 | 执行入口 |
|---|---|---|---|---|
| `status` | 查看服务状态、下一次推送、执行端与队列概览 | 无 | 是 | `status` |
| `push_again` | 立即请求再推一篇（写入队列的待推请求） | 无 | 是 | `push_again` |
| `process_feedback` | 处理飞书侧已提交的反馈 | 无 | 是 | `process_feedback` |
| `pause` | 暂停服务：停止定时推送与飞书响应，控制台仍在前台 | 无 | 是 | `pause` |
| `resume` | 恢复服务并按上次状态继续 | 无 | 是 | `resume` |
| `test_message` | 向已核实 owner 发送一条测试消息 | 无 | 是 | `test_message` |
| `change_schedule` | 修改每日推送时刻（HH:MM，用户时区） | `time`：`HH:MM`，00:00–23:59 | 是 | `change_schedule` |
| `relocate_archive` | 修改资料目录位置 | `path`：非空路径字符串 | 是 | `relocate_archive` |

参数校验失败时拒绝执行并说明原因，例如"参数不合法：参数 time 格式不正确"。
注册表中 `feishu_visible` 为 `false` 的操作即使被意图判定选中，飞书侧也只回复
"请在控制台执行"。

## 指令白名单

短语按 `strip()` 后精确匹配；下表中的空格、大小写与标点不可省略或替换。

| 短语 | 操作 id | 参数 |
|---|---|---|
| `推一篇` | `push_again` | 无 |
| `处理反馈` | `process_feedback` | 无 |
| `状态` | `status` | 无 |

明确**不**命中的例子：`请帮我推一下`、`推 一篇`、`推一篇。`、`状态：`、`STATUS`。
它们进入意图判定，不会直接执行。

## 明确排除

以下动作不在飞书操作集合内；命中这些精确短语时直接拒绝，不进入执行：

| 短语 | 排除原因 | 回执 |
|---|---|---|
| `初始化`、`/frontier-init` | 需要在控制台逐项交互 | 请在控制台执行 |
| `更新知识库`、`/frontier-update-kb` | 需要终端逐条审阅 | 请在控制台执行 |
| `停止服务`、`/frontier-stop` | 关闭控制台即停止服务 | 请在控制台执行 |
| `改代码`、`修改代码`、`修改配置`、`修改权限` | 修改 frontier 自身 | 无权限 |

## 回执与失败

- 成功：操作自己的回执，例如 `push_again` 回"已请求再推一篇（推送请求已记录）。"，
  `status` 回与 `/frontier-status` 相同的快照文本。
- 参数不合法：`参数不合法：<原因>`，且不调用执行入口。
- 未知操作 id：`无权限：该操作不在操作白名单内……`。
- 执行入口抛错：`操作执行失败（<异常类型>: <信息>）。`，控制台继续运行。
- 未命中指令：进入意图判定（#83）。判定命中则发送确认卡片（操作、参数、10 分钟
  过期、一次性 nonce、`执行`/`取消`），owner 点击后才按注册表执行；没有对应操作
  回 `无权限`，无法判断回 `无法判断`。判定运行本身从不执行操作。

## 跨票据边界

- `change_schedule` 只持久化 `push_time`；下一次推送时刻的计算与生效属于 #81。
- `push_again` 记录待推请求；把请求派发成一次 Agent 运行属于 #81 的调度器。
- `pause`/`resume` 只写控制台持久状态；暂停期间"只回暂停提示、不派生任何运行"
  的拦截属于 #81。
- 意图判定运行、确认卡片、nonce/过期与 owner 点击校验属于 #83。
- 本次未搬运既有资料：`relocate_archive` 只校验并记住新位置，重启控制台生效；
  搬移既有 `originals/` 与 `pushes/` 需要单独决定。
