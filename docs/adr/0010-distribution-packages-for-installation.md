# ADR 0010：安装改为发行包，源码仓库只负责开发

- 日期：2026-10-31
- 状态：已接受；实现已在 `spec92-integration` 完成（2026-10-31），真实安装验收待补
- 相关：[ADR 0009](0009-console-as-service.md)（控制台与目录模型）、[ADR 0004](0004-native-windows-python.md)（原生 Windows Python）、[ADR 0007](0007-reuse-configured-lark-cli.md)（复用已配置的 lark-cli）

## 背景

现行安装以 git 为前提：宿主 agent 把仓库 clone 进代码目录，用 uv 建私有环境并装依赖，再生成控制台启动脚本与技能入口指针。这带来三个无法同时满足的需求：

1. **开发**：需要一个处于最前沿、包含 frontier 运行全套文件的目录，可以随意增加功能；其中只有代码值得推送到公开仓库，运行状态与临时产物不属于仓库。
2. **测试安装与使用流程**：需要另一个独立目录来装和用；它如果是 clone，同样只有代码有 git 记录，其余部分没有任何版本证据。
3. **用户安装**：用户机器需要有 git、uv、Python 与可用网络工具链，安装失败面大，且公开仓库的 dev 分支会带着开发内容。

DeepSeek Harness 的插件体系给出了现成参照：**开发用源码仓库，安装用「自包含运行时 + 逐文件摘要清单 + 安装锁」，安装过程不依赖 git**（技能则是按内容摘要锁定、可独立升级的数据资产）。本 ADR 采用同一形态。

## 决策

1. **仓库职责**：GitHub 仓库只放开发输入（源码、技能、契约、文档、测试、构建脚本）。分支模型不变：`dev` 开发、`main` 发布；tag 标记发布。
2. **发布物**：由 CI 在 tag 上构建发行包，内容为源码 + agent 可读资产（`skills/`、`contracts/`、`docs/`）+ 内置 Python 运行时（CPython embeddable + 固定版本依赖 wheel）+ 启动包装器 + 发行包清单（逐文件 sha256、版本、兼容范围）。
3. **用户安装**：从 GitHub Release 下载发行包，校验摘要后解压为代码目录；不 clone、不建私有环境、不安装任何工具链。技能入口指针与控制台启动脚本仍由安装步骤生成。
4. **安装锁**：每次安装写「安装锁」记录版本、制品摘要、渠道、来源、安装时间与兼容范围；它取代安装记录里的 git commit，成为"这台机器装的是哪一版"的证据。源码安装单独标注为源码安装，不伪装成发行包安装。
5. **渠道与版本**：分稳定与预发布两个渠道；测试安装默认取最新预发布，也可显式指定版本。发行包保留最近两个版本，回滚只是切换指针，不重新构建。
6. **源码安装保留**：开发者仍从源码 checkout 运行、用 uv 建私有环境；这条路径只服务开发，不再是 README 给用户的主路径。
7. **发布索引**：Release 挂发行包与摘要文件，并维护一个 `releases/index.json`（版本、渠道、摘要、兼容范围）；v1 不引入包市场或目录网站。

## 考虑过的选项

- **PyInstaller 编译成单文件可执行**：能隐藏 Python，但 agent 运行仍要读 `skills/`、`contracts/`、`docs/`，这些必须外置；调试、热修与升级都更复杂，且要自己解决 PyMuPDF 动态库打包。收益只是隐藏解释器，放弃。
- **wheel + pip/uv 安装**：仍需用户在机器上有可用的 Python 与包管理器，不满足"不需要配置环境"。可作为开发者可选路径，不作为用户主路径。
- **保留 git 安装 + 在 dev→main 合并时过滤不发布文件**：过滤把"不泄漏"寄托在"记得别推 dev"上，且公开仓库的 dev 分支仍会带开发内容；一次失误不可撤销。放弃。
- **把整个安装根目录纳入 git 追踪**：运行状态（队列、心跳、日志、资料登记）持续变化，纳入任何会被推送的仓库只会制造噪音；审计与迁移改用安装锁、运行记录与日志承担。放弃。

## 后果

- **代价**：多一条构建流水线；发行包因内置运行时增大约 40–60 MB；发行包与源码需要一致性校验（清单记录构建来源 commit）；README、安装 prompt、`skills/frontier-run` 的安装参考、`install` 子命令与验收文档都要按本 ADR 改写。
- **收益**：用户安装不依赖 git/uv/Python；测试目录是"装出来的"普通目录，开发、测试、发布、用户安装可以并行；安装版本可审计（摘要 + 渠道）；回滚成本低。
- **不变**：控制台仍是唯一常驻入口（ADR 0009）；飞书仍是唯一存储（ADR 0003）；单执行端约束（ADR 0005）仍要求测试环境使用独立设施，否则测试与正式服务会抢执行端并污染知识库。
