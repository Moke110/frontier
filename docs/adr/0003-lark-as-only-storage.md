# ADR 0003：飞书是唯一存储

- 日期：2026-10-26
- 状态：已接受
- 相关决策：ADR 0002（Bitable 权威）、原文库/推送库分库、配额与离线清理

## 背景

知识五表已迁到 Bitable，但原文与推送仍散在本地：`archive/raw/` 只有文本与页码锚点，PDF 原件在你的研究目录里；`archive/pushes/` 的 HTML 渲染到 `/tmp` 后即弃。结果是**换一台机器就恢复不了**：证据引文指向的原文要靠路径猜，推送件根本不存在。

目标不是"备份"，而是**去掉本地作为必要环节**：任何一台装了 agent 的机器，登录飞书就能继续工作。

## 决策

1. **判定标准**：删掉整个 `$KL_HOME`，系统必须能从飞书完整恢复，且不丢任何用户产生的内容。
2. **不可重建的进飞书**：知识五表、原文 PDF、推送 HTML、推送日志、决定、书目元数据、评分。**可重建的留本地**：正文文本、页码锚点、索引、`raw/*.json` 物化视图、队列状态、缓存、outbox 草稿。
3. **原文库**存 PDF 原件，一篇一行，`paper_id` 唯一；**推送库**存自包含 HTML（图片 base64 内联）+ 同名 Base 行；不存 `push.json`，它的信息全部落进「推送日志」的列。
4. **两库共用配额**：默认 5GB，用户直接改 Base「配置」表。达到 80% 提醒一次；达到 100% 只拦新原文，**不拦推送**；永不自动删除。
5. **清理 = 先备份后删**：下载到 `~/frontier-offline/<日期>/` → 校验 md5 → 状态改 `已离线归档` 并填备份位置 → 才删云盘。本机目录即算离线备份，来源链接与 md5 是重下兜底。
6. **写入顺序：先文件、后 Base 行**；幂等键 `(库, 业务 ID, md5)`；每日四类差异对账（孤儿文件 / 断链 / 重复 / 状态与实物不符）。
7. **读路径：按需下载 + 本地缓存**，命中以 md5 为准，`cache prune` 随时清空。
8. **新模块 `library`** 拥有云盘文件、原文/推送日志/决定/配置四表、配额与对账；`knowledge` 仍管五张知识表；`publisher` 是唯一对外发言者，`library` 只写 alert 文件。
9. **存量**：174 篇 PDF 一次性迁移；15 条测试推送不迁移、不保留；指向测试推送的 `push_id` 置空。切换走"建库 → 回填 → 双写 3 天 → 第 4 天切读"，不与知识五表的 7 天双读捆绑。

10. **单文件上限**：当前租户对 Drive API 的 >20 MB 文件返回 `1061043`。>19 MB 的 PDF 按 19 MB 分片存成 `<paper_id>.pdf.partNN`，顺序与 token 记在「原文」的 `分片` 列；读取时拼接并校验整份 md5。分片是实现细节，不改变"一篇原文一条记录"。

## 被否决的替代方案

- **只把飞书当备份**：本地仍是必要环节，"换机器继续工作"不成立。
- **全量搬进 Base（连队列状态、索引）**：每次状态变更都写飞书，延迟与限流成本换不来任何恢复力。
- **一个 `push.json` 文本列装下推送**：能在 Base 里存，但读不了、搜不了、筛不了；七段正文各占一列才配得上"可浏览"。
- **把拒绝理由塞回推送日志的提议列**：草稿与终态混在一格，写入必然互相覆盖；决定独立成表，按提议粒度留痕。
- **原文采用"有引用才收"**：推送完、证据未产生的窗口里会出现无档论文，回查断档。
- **删除自动执行**：一次误判就永久丢原件；配额是自设预算，不值得用不可逆动作去守。
- **全量镜像到本地**：读路径简单，但由"本地可丢"退回"本地必须存在"，且为不读的文件付下载成本。
- **按年月分目录**：人工翻找方便，但移动文件可能换 token，Base 链接失效 —— 正是本方案要避免的失败。

## 后果

- Base 多三张表（原文 / 推送日志 / 决定）与一行配置；`papers` 改名「报道」并加原文关联。
- `archive` 从"四层存储"退为"本地缓存与物化视图"；`writer render` 的输出从 PDF 改为自包含 HTML。
- 证据的可回查性依赖 md5 与来源链接，而不是本地路径；重建文本与锚点的成本约 1 秒/篇。
- 原文库初始占配额 1.5GB（≈30%），推送件按每次几 MB 增长。
- 配额、对账、上传都必须能在 `FixtureDrive` 上离线测试，不能依赖真实租户。
- 单文件上限是租户属性，不是 code 常量：换租户若支持 100 MB，可把 19 MB 调大，已存的旧分片仍可读。
