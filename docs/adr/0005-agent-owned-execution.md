# ADR 0005：由宿主 agent 承担 frontier 的安装与运行

- 日期：2026-10-27
- 状态：已接受；安装方式已确认，尚未实施与完成部署验收
- 替代：ADR 0004 第 5 条的任务计划程序方案；其余原生 Windows 兼容决策继续有效
- 2026-10-29：第 11 条"不创建独立常驻程序"由 [ADR 0008](0008-listener-process.md) 修订为"允许用户手动启停的单一监听进程"；其余约束继续有效

frontier 面向无编程背景的研究者，提供知识库与论文报道推送。用户把一段安装 prompt 交给宿主 agent，由 agent 获取代码、安装飞书 CLI、引导登录、管理私有依赖并验证安装；用户无需自行配置环境或打开终端。

配套 agent 必须确认具备内置定时任务能力，同时能够在 Windows 本地执行 frontier 与飞书 CLI。2026-10-27 用户据此撤回首批支持 OpenCode 的选择，改以 ChatGPT、WorkBuddy 等满足条件的 agent 为目标；具体产品模式与版本按官方能力和安装验收确定，不能仅凭产品名称宣称支持。frontier 由宿主 agent 执行；宿主关闭期间不承诺即时推送或处理反馈。

允许 agent 管理安装工作区及用户确认的数据根中的私有依赖、配置和缓存，并按宿主支持的方式注册运行技能；不修改系统或用户环境变量、PATH、注册表，不注册服务或系统定时任务，不创建独立常驻程序。用户参与必要的登录、授权和知识库选择。此取舍以宿主运行期间的可用性，换取简单、可迁移的安装与运行方式。

迁移验收同时覆盖本机恢复既有飞书知识库，以及新用户通过安装 prompt 完成 CLI 安装、登录指引和知识库初始化。飞书继续作为权威存储，已有数据必须保持完整。

## 已确认的运行与安装体验

- 反馈以飞书多维表格中持久保存的记录为准，推送附对应入口；agent 下次运行读取并处理。实时按钮只作为后续增强，不是基本流程的必要条件。保留先评分、再确认更新的顺序。
- 一段 prompt 启动安装，agent 全程引导。必须由用户完成的登录、授权或管理员批准步骤提供直达链接与明确说明，保存进度以便继续；存在阻塞项时不得宣称安装成功。
- 定时任务是标准安装步骤：集中确认时区、每日推送时间、反馈检查频率与启用状态后创建并启用；用户可以选择暂不启用。此项于 2026-10-27 安装方式访谈中替代“默认手动运行、定时可选”的约定。每次先处理反馈、恢复未完成工作，再检索推送。错过多天最多合并成一次待推请求；未回答的问题继续阻止新推送。
- 安装提供创建知识库与连接已有知识库两条路径。连接已有库时用户提供飞书知识库链接，由 agent 校验权限、结构并恢复。新库从空设施开始，先完成临时数据的端到端测试并清理，再以用户文献库和要求初始化正式知识内容；不把测试样例保留在正式知识库中。

## 已确认的可靠性边界

- 首版单用户、单执行端；切换设备或 agent 前先结束旧端执行，再由新端接管，不支持多端同时写入或多人协作。
- 反馈具有明确的提交动作，提交前可修改；agent 仅处理已提交反馈并记录结果。处理完成后修改表格不自动撤销知识更新，更正须走新的更正请求。
- 已发出的待答问题、更新提议、已提交反馈及处理结果必须持久保存在飞书，本地仅为可重建副本。换机继续原问题，不重发已完成推送；尚未发出的生成草稿可以重新生成。这细化并修正 ADR 0003 第 2 条中队列状态仅存本地的假设。
- 自动重试仅限可安全重复的步骤。消息发送结果不明确时先核对记录，仍无法确认则暂停该项并报告；网络或授权恢复后从已完成位置继续。

## 默认调度与授权

- 每日 08:00（用户所在时区）触发检索推送；每小时检查反馈和未完成工作，每日首次小时检查同时完成维护，无变化时保持安静。只创建这两类任务，不另建维护任务；未答问题不阻止维护。用户可随时手动要求处理反馈。安装结束时统一确认时区、执行时间和启用状态。
- 安装时说明并取得日常运行授权，范围包括读取论文和知识库、发送推送、保存记录、应用用户已提交采纳的更新。安装测试成功后的清理属于已确认的测试流程，仅限本次测试产物；删除正式云端资料、扩大权限或改变部署方式另行确认。
- 优先限定工作目录和必要权限；若宿主不能支持必要的执行授权，则不能宣称通过自动运行验收。
- 当前对话仅确认产品设计，尚未在本机创建或启用实际定时任务。

上述产品决策已经用户确认；当前实施与验收状态见 GitHub Issues 和 `docs/acceptance/`，发现会改变上述用户体验的技术限制时重新讨论。本决策不代表所有能力均已通过真实验收。现行用户入口为根目录 `README.md`，运行时入口为 `skills/frontier-run/SKILL.md`；原 INSTALL 与 Windows 交接文档不再作为当前操作指引。

## 安装方式细化（2026-10-27，已确认设计，离线实现完成，真实验收待续）

用户先以安装工作区 `<root>` 为源文件夹创建宿主项目，再发送安装 prompt。Agent 将仓库获取到 `<root>/frontier/`，默认数据根为 `<root>/frontier-archive/`；用户可另选数据根，其中缓存与离线备份必须明确区分。

运行技能统一采用 `frontier-{name}` 命名，本次将现有单入口改名为 `frontier-run`，安装、推送、反馈和维护继续通过其参考文档组织，不额外拆分技能。Agent 将技能接入宿主可识别的目录，并实际验证能读取入口及参考文件；技能接入后仍须能定位真实代码目录，不得依赖其复制前的相对位置。部署统一使用 uv：优先复用可用的 uv，否则安装在工作区内，由 uv 管理 Python 与仓库内独立环境，任务使用记录的完整路径。目录改名、`frontier-run` 入口指针与 uv 私有环境已按此实现；真实宿主上的技能发现与调度触发仍由 #49/#50 验收。

安装验收分阶段进行：创建设施前检查技能加载、运行环境、CLI 安装、登录与必要权限，记为安装预检；缺失项由 Agent 安装或引导登录授权，尽量通过直达链接与界面完成，不要求用户自己走终端。设施创建后验证真实论文推送、飞书记录与文件读写；用户在飞书检查展示并提交反馈后，再验证 Agent 处理结果并修复发现的问题。预检不替代真实资源操作的权限验证，未实测项必须保留为待验收。

安装保留新建与接入已有知识库两条路径；新建前确认数据根及设施名称，由 Agent 创建 Base 本身、各表和云盘目录，遇到登录、管理员授权或界面限制时引导用户完成后续接；接入已有库时按链接校验并复用。重复发送安装 prompt 应继续已保存进度，不重复创建表、目录或任务。Base、各表与云盘目录允许用户自定义展示名称，提供默认值供集中确认；以稳定 ID 识别设施，内部字段结构由 frontier 管理。该路径已由 `facilities` 实现并通过离线测试，真实租户验证仍待续。

知识内容初始化不作为安装测试的前置条件：用户先提供一个关键词或检索式，以临时知识卡片走完真实检索、推送、评分、更新提议、用户采纳和写入的端到端闭环。临时测试数据与正式数据必须可区分，不能借测试修改已有正式内容。

测试成功后，清理本次测试生成的本地文件、飞书记录、上传文件及可撤回的测试消息，临时知识卡片及其更新结果也全部清理。保留安装环境、配置与空设施，只保留不含论文内容的验收状态以便续接；已有正式数据不属于清理范围。任何产物无法删除时明确报告清理未完成，不得宣称已全部清理。测试失败时按既有可恢复安装规则修复并续接，未通过不得进入成功后的初始化阶段。

端到端测试与清理成功后，进入知识库初始化步骤：根据用户提供的文献库（原文 PDF、文本或索引列表）及直接输入的要求，提炼知识卡片，经用户确认后写入正式知识库，再按照标准流程执行检索。checkpoint 沿用现有词义，指知识卡片 ID 的旧称，不恢复独立实体。已有库接入保留原内容，不因安装而重建或清空知识库。

每日推送使用正式知识库的标准检索流程，安装测试检索式不自动成为日常输入；正式知识内容尚未就绪时不得以测试检索代替日常推送。自动运行验收与交互流程验收分别报告：任务创建后须等待一次真实宿主定时触发，验证本地访问、技能加载与飞书操作，不能用手动运行代替。尚未触发时标为“自动运行待验收”，用户无需一直守着安装对话。

上述记录只确认设计，不宣称安装或宿主验收已通过。

## 宿主能力核查（2026-10-27）

- ChatGPT Windows 桌面端的本地执行模式：官方文档确认支持本地项目、skills 和定时任务；需要电脑开机且应用运行。网页云端任务不能直接使用本机文件夹。依据：[定时任务](https://learn.chatgpt.com/docs/automations)、[Windows 桌面端](https://learn.chatgpt.com/docs/app/windows)。修正此前将 ChatGPT 一律解释为 Codex 的表述。
- WorkBuddy Windows 本地任务：官方文档确认可按计划在指定工作目录运行 Agent，权限模式支持终端和外部程序；需要电脑与客户端保持运行。云端任务不能代替对本地依赖的访问。依据：[自动化](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)、[权限模式](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)。
- 上述属于文档层面的能力确认，不等于 frontier 已完成两款宿主的端到端验收。安装时还需检查当前账号、版本、权限及真实的本地定时执行能力。

## 修订：私有环境移入数据根（2026-10-27）

首发验收在 DeepSeek Harness 上发现：宿主限制**位于工作区内部的可执行文件**的写入范围，仓库内解释器无法创建数据根、也无法写飞书 CLI 的令牌存储，`install workspace` 因此失败。因此本文第 42 条与安装细化中"仓库内独立环境"的表述修订为：**私有 uv 环境与解释器放在数据根内，代码目录只保留代码**；uv 从工作区外解析，解释器绝对路径写入工作区指针记录与安装配置。

代码与数据仍然分离，仍不修改系统或用户环境变量、PATH、注册表，也不注册服务或系统任务；改变的只是私有环境的位置。实施规格见 [首次真实安装 #51](https://github.com/Moke110/frontier/issues/51)，宿主选择见 [ADR 0006](0006-deepseek-harness-as-a-host.md)。
