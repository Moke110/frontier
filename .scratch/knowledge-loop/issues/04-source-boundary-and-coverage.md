# 04 信息源边界与覆盖策略

Type: grilling ｜ Status: resolved ｜ Blocked by: —
Claimed by: Hermes (session 2026-10-16)

## Question

票 03 定下了「检索什么」（checkpoint 的 ontology）与「怎么判准」（annotation）。本票定**去哪查、查多少**。

## 实测（Hermes 在提问前跑的，不是推测）

| 测试 | 结果 |
|---|---|
| Europe PMC `SRC:PPR`（预印本源）是否可用 | ✅ 16 天窗口 **11,870 条**预印本 —— **预印本无需接新 API，一个 query 子句即可覆盖** |
| `"HMBS"` 不限字段，近 30 天 | **7 条**，头两条是「CRRT 期间美罗培南给药优化」「大剂量甲氨蝶呤药代模型」—— **完全跑偏**（Europe PMC 默认搜**全文**） |
| `TITLE_ABS:"HMBS"` 同窗口 | **1 条，正中靶心**：「静脉输注血红素预防急性肝性卟啉症频繁发作」 |

→ **结论一**：ontology 查询**必须限定字段**（Europe PMC `TITLE_ABS:` / PubMed `[tiab]`），否则召回噪音压倒信号。
→ **结论二**：即使限定字段，**annotation 消歧仍然必需** —— 这次干净是运气，不是保证。

## Answer

**三个决定（用户）：**

| 问题 | 决定 |
|---|---|
| ① 信息源边界 | **A —— arXiv（q-bio / cs）+ Europe PMC 全源（`MED` + `PMC` + `PPR` 预印本）**，全部查询限定 `TITLE_ABS` |
| ② 覆盖策略 | **A —— 全域检索 + 发送侧限额**：每 tick 查全部 `enabled` checkpoint，候选入池，再由排序选出发送 |
| ③ 同义词扩展 | **A —— 允许 agent 提议，但必须附「实测精确率」**（拿候选词去查，报出前 10 条里 annotation 判为命中的比例），**且只能用户确认后写入**；一次最多提 2–3 条 |

**为什么选②全域（本票的核心论证）** —— **「查」很便宜，「写」才贵**：

- 一次 checkpoint 查询 = 2 次 API 调用；**N=10 → 每天 20 次**，N=30 → 60 次。相对 Europe PMC / arXiv 的容量属小菜（旧系统每天才 2–4 次）
- 真正贵的是「每篇要 LLM 写四要点」—— 那个成本由「**发几张卡**」决定（票 09），**与查几个 checkpoint 无关**
- 而**轮换会让「评分反哺」失去一半用武之地**：轮换下评分只能学「域内」，学不到「**域间怎么分配注意力**」—— 而后者恰恰是最想要它学的
- **一句话：全域把「怎么知道系统在变好」从不可优化变成可优化。**

**为什么选③「提议 + 实测精确率」**：这是唯一能用**客观证据**约束主观扩词的办法 —— 不是「我觉得这个词相关」，而是「用这个词查，70% 的命中都通过了你的判据」。扩词因此也变成可验证的；且 `hit_rate` 变化可归因（词变了 → 命中率怎么变，链不断）。

**连带约束（写进 spec）**：

1. 查询模板统一带字段限定 + 日期窗口（`FIRST_PDATE`；arXiv 的 `submittedDate` 不能带连字符）
2. **不做轮换调度器** —— 全域，因此 `last_checked` 只用于「观测覆盖情况」，不用于调度
3. 去重仍靠 `archive/papers.jsonl`（键 `source:source_id`）
4. 质量过滤沿用 `literature-apis` skill 的既有规则（Journal Article / 标题黑名单 / 必须有 pmid）
5. 预印本（`PPR`）进入候选池后，卡片上要**标明是否为预印本**（未同行评审）

**残留未决（不阻塞本票，但 spec 需要数字）**：

- **checkpoint 初始规模**（用户未答）—— 直接决定每日 API 调用数与候选池大小；建议先 8–12 个
- **每 checkpoint 每源的单次查询上限**（如 top 20）—— 决定池子上限
- **`PPR` 是否默认纳入候选**还是仅做标记（预印本质量参差，可能拉低命中率）
