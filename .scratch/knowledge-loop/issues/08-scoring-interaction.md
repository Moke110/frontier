# 08 评分交互与信号格式（含入站语法：打分 + 追问）

Type: grilling ｜ Status: open ｜ Blocked by: 01, 02

> 📌 **票 01 已结（B 卡片流）→ 本票的问题形状＝「卡片发出去之后，我怎么回、系统怎么懂」**，而不是 C 分级路线的「回编号打分」（那条已作废）。
>
> 📌 **票 10 已结（发送机制）**：① 引用回复**不带任何消息 id**（只把被引文字内联为 `[引用: …]`），`reply_to` 被忽略，出站 message_id 是自造 uuid → **不能靠引用定位**；② 卡片走 `hermes send` 直发，**不进会话历史** → `attach_to_session` 镜像**对卡片流无效**。
>
> 📌 **票 02 已结（评分采集）**：微信**无按钮、无快捷回复、无 reaction**；唯一被官方机制认可的**结构化输入 = 「编号列表 + 回数字」**（`clarify` 工具的**文本回退**路径 —— `weixin.py` 未实现 `send_clarify`）。另：**入站 3 秒内的多条快发会被合并成一条**（`\n` 拼接）；旧日报正文实测 4152–5763 字符 → **一次投递被切成 2 条气泡，且气泡 ≠ 条目**。
>
> 🔑 **两票的「表面冲突」已解，解法是本票的框架约束**：
> 票 02 说「靠编号定位，但**必须开 `attach_to_session`** 否则 agent 对简报失忆」；票 10 说卡片流**不进会话历史**。同一个目标（agent 必须知道「编号 ↔ 卡片」的对应），票 02 的桥在卡片流下**不可用**。
> **→ 桥必须换成「当日推送的 manifest 文件」**（卡片发出时同步落盘，如 `runs/<date>.json` / `digests/<date>_cards.json`）。
> **这是净收益**：(a) `attach_to_session` 属 **Hermes 专有**（票 06 判定），manifest 文件**换任何 agent 都成立**；(b) 它与票 06 推荐的「状态机 + `runs/<date>.json`」**是同一个东西，一物两用**；(c) 它把粒度从「整篇简报一个 turn」提升到**卡片级**。

## Question

设计**统一的入站语法**：用户在同一个 DM 里回话，系统必须能分辨「**这在给哪张卡打分**」/「**这在追问某张卡**」/「**这是别的一般指令**」。

要定：

- **卡片内嵌 id 的形式** —— 序号（`#3`）？原始文献 id（`arxiv:2610.10482`）？两者都带？要求：**稳定、唯一、一眼能抄**（用户要在一个 token 里表达它）
- **打分维度** —— 票 02 建议**二元（👍/👎 或 `+`/`-`）+ 可选一句话**（业界一致：多档强制打分回收率最低）；你要不要多维（相关/新颖/可读）
- **打分方式** —— 一条消息打完（`1👍 2👎 3👍 4👎`，**票 02 推荐**，且规避 3 秒防抖合并）vs 逐条回
- **追问与打分的区分** —— 「回 `4`」是打分还是「讲讲第 4 篇」？靠语法（`4👍` vs `?4`）还是靠有无内容？
- **负信号** —— 「我没读」/「不感兴趣」/「太水」要不要显式区分？（票 02 提醒：沉默既可能是没看也可能是不要，**有偏**）
- **隐式信号** —— 票 02 建议把「**是否追问该条目**」当**最强正信号**记录；要不要、以及怎么与显式评分合成
- **摩擦预算** —— 超过几步我就不会打分了（本票的核心约束）
- **改分 / 打错**怎么办
- **冷启动期**没有评分时的行为
- **裸回复**（不写编号）如何处理 —— 算最近一张卡？还是当天全部？还是要求必须带编号？
- **manifest 的粒度** —— 卡片级 store 需要哪些字段，才能让 agent 从 `1👍` 精确还原出「你评的是哪篇」（与票 12 的状态机对齐）
