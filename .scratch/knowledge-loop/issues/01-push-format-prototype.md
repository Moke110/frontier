# 01 推送形态（三种样张对比）

Type: prototype ｜ Status: resolved ｜ Blocked by: —
Claimed by: Hermes (session 2026-10-16)

## Question

推送的**形态**该是什么样，才能让我（读者）真的读完并打分？

判据是「读完 + 给出评分」，所以形态不是审美问题，是整套系统的**前提条件**。用**同一批候选文献**渲染 2–3 种低成本样张供我对比：

- **候选 A · 单条长日报**（旧 paper_digest 形态：每天 4 篇 × 「做了什么 / 发现 / 为什么重要 / 保留」+ 串回历史脉络）
- **候选 B · 卡片流**（一条消息一篇，可逐条引用回复打分）
- **候选 C · 分级摘要**（顶部 3 行结论 + 可展开细节；或「1 篇深读 + N 篇一句话」）

对比维度：读完所需时间 · 我**读完的可能性** · 打分的顺手程度 · 信息密度 · 与「可追问」的兼容性（旧系统靠 `attach_to_session` 支持回复「讲下第 2 篇」）。

**产出**：`.scratch/knowledge-loop/prototypes/` 下的样张文件（从本票链接），以及三种形态的取舍判断。

## Answer

**决策：采用 B · 卡片流（一条消息一篇，逐条引用打分）。** 用户在三种样张对比后选 B，并明确接受由此产生的消息量。

**理由链**：

- 判据是「读完 + 打分」，而 **A（长日报）的致命伤是打分粒度** —— 整批只能给一个分 → 无法归因到单篇或单域 → **评分反哺检索的链路断掉**。A 当年跑得动，是因为它只需「读」，不含「闭环」这一层要求。
- B 让打分入口就落在每张卡片下方（最顺手），且天然支持「逐条引用」→ **单篇级信号**，这是评分反哺唯一可用的输入。
- C（分级摘要）被否决：其「30 秒版」虽最省时，但每天只喂 1 篇纵深，用户不取。

**连带后果（本票最重要的产出是这些耦合）**：

1. **票 08 的问题形状随之确定**：变成「怎么用**引用 / 逐条回复**打分最省力」，而非「回编号打分」（C 路线）。C 的「30 秒版」形态随之作废。
2. **新增票 09（每日条数与发送节奏）** —— B 一旦选定，「一天发几条、连发还是分批」立刻成为可精确提问的决策；该雾点从 Not yet specified **毕业**。
3. **新增票 10（多条发送机制，research）** —— 一次 cron tick 要发出 N 张独立卡片，这是 **B 路线最大的可行性风险**（Hermes 最终回复默认只发一条消息）。
4. 旧系统实物（`~/.hermes/cron/output/5765d8701ebd_20261009_083442.txt`）**不再作为形态目标**，但仍是**内容深度基准** —— 卡片正文的信息量不应低于旧日报的对应段落。

**原型产物**：`.scratch/knowledge-loop/prototypes/`（`B-card-stream.md` · `C-tiered.md` · `README.md` 含对比表与未验证假设）。A 形态用旧日报实物代替，未重做。

**未验证项（继承给后续票）**：卡片流的真机渲染效果、消息疲劳的实际程度、「连发 N 条」的机制可行性（→ 票 10）。
