# 票 01 原型说明（三种推送形态）

> 原型 · 一次性产物，不是生产代码。用**同一批内容**渲染，隔离「形态」这一个变量。

## 素材选择（为什么用这批）

用 **2026-10-09 那批 4 篇论文**（Truecell / scXMatch / Galectin-7 轴 / CatBoost 肝纤维化）——

**你对这批内容已经熟悉**（旧日报推过），所以你的反馈是**纯粹对形态**的，不会被「内容新不新鲜」污染。这是刻意的实验设计，不是偷懒。

## 三种形态的实物

| 形态 | 实物位置 | 说明 |
|---|---|---|
| **A · 单条长日报** | **无需重做** —— 见 `~/.hermes/cron/output/5765d8701ebd_20261009_083442.txt`（约 5,000 字） | 旧系统真实形态：一条消息装 4 篇，每篇「做了什么 / 发现 / 为什么重要 / 保留」四段，末尾附「本次略过的候选」+ 归档核对。**你当时真的收到过它** |
| **B · 卡片流** | `prototypes/B-card-stream.md` | 一条消息一篇，4 条/批，每篇压到 4 个要点，末尾带打分入口（占位） |
| **C · 分级摘要** | `prototypes/C-tiered.md` | 一次推送：顶部「30 秒版」4 篇一句话 + ▸星级；正文只深读 1 篇；其余可展开 |

## 对比（我的判断，待你实测覆盖）

| 维度 | A 长日报 | B 卡片流 | C 分级 |
|---|---|---|---|
| 读完所需时间 | 5–8 分钟（需滚动很久） | 4 × 30 秒，可只读感兴趣的那条 | 30 秒可扫完，深读 1 篇再花 2 分钟 |
| 我**读完的可能性** | 低（一屏装不下，容易「稍后读」= 永不读） | 中（有**消息疲劳**风险：4 条未读/天 ≈ 1,400 条/年） | **高**（30 秒版给「今天值不值得细看」的判据） |
| 打分粒度 | **粗 —— 只能给整批一个分** | 细 —— 每篇一个分 | 细 —— 每篇可给分（回编号），且天然提示了打分点 |
| 打分顺手度 | 低（读完 5 篇已累，再想打分） | 高（就在那条卡片下方回复） | 高（回一个数字即可） |
| 信息密度 | 高（但被淹没，实际吸收率低） | 中（每篇被压缩，可能丢失关键的「保留」质疑） | 高（30 秒版给索引，深读给纵深） |
| 可追问兼容 | 高（旧系统靠此跑通：「讲下第 2 篇」） | 高（直接回复某条卡片） | 高（回复编号） |
| 实现成本 | 最低（旧系统已验证） | 低（cron 内多条发送） | 中（要产两段内容：摘要句 + 深读块） |
| 主要失败模式 | **一条长文被划走，且整批一个分 → 信号无法归因到「哪篇/哪个域」→ 评分反哺检索这条链断掉** | 消息噪音 → 干脆不看 → 打分为零 | 每天只喂 1 篇纵深，可能觉得「给少了」 |

## 我的推荐

**C 为骨架 + 借用 B 的「按篇回编号打分」语法。**

理由：判据是「**读完 + 打分**」，而 **A 的致命伤是打分粒度**——整批一个分，无法归因到单篇或单域，评分反哺（票 08 之后的所有雾）就没了输入。C 是唯一同时让「读完」与「打分」都变便宜的形态；B 的打分语法正好补 C 的入口。

## 与票 08 的耦合（重要）

选 C 会**改变票 08 的问题形状**：
- 若选 B → 08 变成「怎么用**引用/逐条回复**打分」
- 若选 C → 08 变成「怎么用**回编号**打分最省力」，且「没回复」本身是一个可用的弱负信号

所以这两张票必须串起来看，不能各自拍板。
