# frontier

面向研究者的知识库与论文报道推送系统。围绕你关注的知识卡片检索论文，由 agent 排序、撰写报道并推送到飞书；你评分、确认更新后，研究知识逐步积累为命题与证据。

frontier 依赖一款能在本机执行命令、使用技能并创建定时任务的 agent，以及飞书 CLI。代码与依赖由 agent 管理，你无需自己配置环境或打开终端。飞书保存知识、原文、推送件和已发出的待答问题，本地保存可重建副本。

## 安装

在 Windows 上打开宿主 agent 的本地会话，把下面整段发给它：

```text
请帮我安装 frontier：

1. 在我要用的工作区里获取代码；已有副本时先检查来源和本地改动，不覆盖用户数据。代码与数据分开，记录两者的完整路径。
2. 读取仓库的 README.md，再加载 skills/frontier-run/SKILL.md，按它引用的安装流程操作。
3. 检查当前宿主是否支持本地命令、技能和内置定时任务。优先复用工作区外可用的 uv，否则装进数据根；用 uv 在数据根建私有 Python 环境并安装依赖，解释器的完整路径写进安装记录。自动准备飞书 CLI，不修改系统/用户环境变量、PATH、注册表，不装服务、系统定时任务或登录自启；唯一常驻组件是给我手动启停的 `frontier-listener` 监听进程。
4. 引导我完成飞书登录和必要授权，并用预检分别说明 CLI、登录、授权范围和真实资源读取。由你创建 Base、表和两个云盘目录；先让我确认数据根和展示名称，名称可改。已有知识库则按链接检查后接入，不清空、不重建。
5. 用我提供的关键词或检索式做一次临时推送：写临时知识卡片，走真实检索、推送、飞书展示、评分与采纳写入；完成后按测试标识清理本次产物并读回确认。测试不通过或清理不干净就不要进入正式初始化。
6. 测试与清理通过后，接收我的 PDF、文本或索引列表和直接要求，提炼正式知识卡片给我确认；确认后写入飞书并完成一次标准检索。已有知识保留。
7. 生成监听进程的启停脚本（`frontier-listener.cmd` / `frontier-listener-stop.cmd`），说明它 24 小时消费飞书命令（`推一篇`、`处理反馈`、`状态`），由我双击启动、双击停止，窗口标题固定便于识别；不装服务、不登录自启。展示用户时区内每日 08:00 推送与每日 09:00 监听巡检两个瞬时任务的计划。我确认后再创建这两个真实任务，每个任务加载同一份 frontier-run，在指定仓库与数据根执行一次后退出，不挂会话。反馈处理由监听进程每 5 分钟完成，不再有每小时任务。
8. 等我确认并启动监听进程后，实际发一条飞书命令验证闭环；等待每日推送与监听巡检各至少一次真实到点运行，再报告自动运行通过。把任务创建、标志位、手动调用与真实触发分开。中断后保留进度，汇报已可用、阻塞与未实测项。
```

需要你亲自完成的步骤包括登录、管理员授权、确认数据根与展示名称、用关键词发起验收、确认正式知识卡片、以及确认时区与自动运行权限。新建模式不再要求你先准备空 Base：agent 创建 Base 本身和表，也可以接入已有库。

| 目标宿主 | 所需模式 | 当前验证状态 |
|---|---|---|
| ChatGPT Windows 桌面端 | 本地执行 + 内置定时任务 | 完整安装与真实调度尚未实测 |
| WorkBuddy Windows 桌面端 | 本地会话 + 内置自动化 | 本地命令与项目访问有历史记录；真实定时触发和无人值守权限仍待验收 |
| DeepSeek Harness（本机会话） | 本地命令 + 技能 + 会话内定时 + 用户启停的监听进程 | 2026-10-27 起作为第三款运行宿主（[ADR 0006](docs/adr/0006-deepseek-harness-as-a-host.md)）；首次 Windows 安装验收执行中 |

具体版本、账号权限和证据见 [宿主验收记录](docs/acceptance/README.md)。电脑须开机、宿主运行且能访问飞书；网页云任务不能代替对本机依赖和凭据的访问。OpenCode 不在首批定时部署支持范围。

每个定时任务只做一次有界运行后退出，不长期挂着会话。24 小时在线由监听进程提供：它由你手动启动和停止，宿主所在机器重启后需要你重新启动（或由次日巡检发现并尝试拉起一次）。详见 [ADR 0008](docs/adr/0008-listener-process.md)。

每款宿主独立验收，一款宿主的成功不能证明另一款可用。数据根内的私有环境用于隔离依赖，并不能解除宿主沙箱限制；安装前必须实测宿主对数据根和飞书 CLI 凭据存储（含令牌与 DPoP 密钥）的必要写入权限，受限时报告阻塞并在授权范围内解决。

## 使用

两种操作方式：

- **飞书私聊（24 小时，只要监听进程在跑）**：给 frontier 机器人发 `推一篇`、`处理反馈`、`状态`。监听进程只认你本人的单聊消息，其他人和群聊一律忽略；需要判断的工作会当场拉起一次宿主运行并在飞书回执。
- **安装时的宿主会话**：直接说“运行 frontier，再推一篇”“处理 frontier 的反馈”“查看 frontier 的安装状态和待答问题”“暂停 frontier 的自动任务”。

监听进程通过数据根里的 `bin\frontier-listener.cmd` 启动（窗口标题 `frontier-listener`），用 `bin\frontier-listener-stop.cmd`、`Ctrl+C` 或关闭窗口停止。它不是 Windows 服务，不随开机启动；机器重启后需要你重新双击启动。

每日 08:00 任务请求一篇推送；反馈由监听进程每 5 分钟处理，当天首次同时做维护（原文库、推送库和配额）；每日 09:00 任务检查监听是否在线，不在线会尝试拉起一次并如实报告。没有变化时保持安静。错过多天最多合并成一次待推请求，不连续补发。

每篇推送附反馈入口。先评分，再逐题确认知识更新；编辑答案后须明确提交，agent 下次运行才处理。只有采纳的提议会更新知识库。“不在关注领域”会丢弃该篇的更新题。未回答的问题会挡住下一篇推送，但不阻止存储维护。

已处理的答案不会因后来编辑表格而自动撤销；需要纠正时，请向 agent 提出新的更正请求。发送超时且结果不明时，agent 应先核对，无法确认则报告并暂停该项。

## 暂停、换机与恢复

暂停时，先停止监听进程，再让宿主停用 frontier 的两个定时任务。换机或换宿主时，先停止旧端的监听进程与定时任务，再在新端运行安装 prompt，选择连接已有飞书知识库，由 agent 完成接管与恢复。同一知识库同时只使用一个执行端。

本地缓存可以重建；离线备份可能是已从云盘移除的原文的唯一副本，须单独保留。卸载运行配置不会自动删除飞书数据。删除云端原文需要单独确认，并先完成离线备份与校验。

## 遇到问题

把问题交给宿主 agent，并让它读取安装报告：

- **阻塞**：缺依赖、未登录、权限不足等，需要修复后继续。
- **未实测**：没有真实运行证据；任务已配置不等于触发成功。
- **队列未推进**：检查答案是否已提交，以及是否存在更早的待答问题。
- **飞书命令没反应**：先用数据根里的 `frontier-listener.cmd` 启动监听进程（窗口标题 `frontier-listener`），再看每日 09:00 巡检报告；监听不在线时反馈会堆积，直到它恢复。

数据根默认在工作区的 `frontier-archive`，代码默认在工作区的 `frontier`；安装时 agent 会记录实际位置。私有 Python 环境与解释器在数据根内，代码目录只保留代码；uv 优先复用工作区外的可用副本。中断后可要求“继续 frontier 安装”，不必从头创建知识库。存量迁移和云端恢复的限制见 [恢复验收记录](docs/acceptance/README.md)。
